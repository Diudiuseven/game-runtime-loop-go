# game-runtime-loop-go

可复现的游戏运行时主循环：按**固定时间步**推进逻辑，把逻辑更新与外部渲染/采样节奏解耦。
不依赖任何外部引擎，整条链路可在本地用 `go test` 确定性复现与验证。

## 时间模型

```
真实时钟增量 ──×scale──▶ 累加器(acc) ──整步兑换──▶ 逻辑步(step 0,1,2,...)
```

- 逻辑状态**只**由推进的时间步序列与调度到各步的输入决定，与真实时钟、
  渲染节奏、单次循环耗时无关。相同输入序列在任何机器上得到一致的状态轨迹。
- 每次 `Pump()` 读取时钟增量，乘以时间缩放系数后进入累加器；
  累加器只按整数个 `StepDuration` 兑换逻辑步，不足一步的余量保留到下次。
- 输入通过 `SubmitInput(atStep, in)` 按**目标步号**调度，而非按到达时间，
  因此输入的生效点与驱动节奏无关。
- 暂停：`Pause()` 后逻辑时间完全停止，暂停期间的真实时间在 `Resume()` 时被丢弃，
  不会形成追帧债务。`Resume()` 从恢复时刻重新计时。
- 缩放：`SetScale(s)`（`s >= 0`）只改变累积速率，推进仍落在固定步长上；
  `s = 0` 等价于停止累积，但与 `Pause` 在 `Stats` 中可区分。
  缩放切换不影响累加器中已有的余量。

## 追帧与过载

单次 `Pump` 兑换的步数受 `MaxStepsPerPump` 上界约束（帧预算）。
卡顿后欠债超出上界时按 `CatchUpPolicy` 处理，**绝不静默丢失**：

| 策略 | 行为 |
|---|---|
| `CatchUpDrop` | 超出上界的累积时间直接丢弃，`Result.StepsDropped` 报告丢弃步数 |
| `CatchUpDefer` | 欠债留到后续 Pump 逐帧消化（降级），`Result.Overloaded=true` 期间可观测；债务总量受 `MaxAccumulatedSteps` 约束，超限部分丢弃并报告 |

突发请求（时钟未前进的连续 `Pump`）是确定性的空操作；空闲期累积的时间
按上述策略有界消化，不会无限延迟也不会无限堆积。

## 调度语义

- 系统经 `RegisterSystem` 注册，**执行顺序恒等于注册顺序**，不受其他因素影响。
- 每一步是**事务**：步初对状态做检查点，任一系统返回错误或 panic，
  本步整体回滚——后续系统与外部观察者都不会看到半更新状态；
  panic 被恢复并包装为 `StepError{Panic: true}`。
- 出错后的隔离策略由 `ErrorPolicy` 决定：
  - `ErrorAbort`：回滚并中止本次 Pump，错误经 `Result.Err` 上报，状态停在上一个已提交步；
  - `ErrorSkipStep`：回滚后跳过该步继续推进，跳过事件经 `OnEvent` 上报。

## 热更新

- `SwapSystem(name, next)` 请求在**下一个步边界**生效；单线程驱动模型下，
  处于中间状态的步对外不可见，更新前后逻辑时间与状态天然对齐。
- 新版本进入"试用期"：若开启 `HotSwapRollback`，新版本首次执行出错时
  自动回退到上一可用版本并重试本步，循环不中断，回退经 `EventSwapRolledBack` 上报。

## 快照与恢复

`Snapshot()` 深拷贝步号、累加器、暂停/缩放、状态与未消费输入；
`Restore(snap)` 后从同一点继续推进，后续轨迹与不中断时完全一致。
快照本身不被恢复消耗，可重复使用。注意：快照不捕获系统实现版本。

## 配置项

| 字段 | 默认 | 说明 |
|---|---|---|
| `StepDuration` | 1/60s | 固定逻辑步长 |
| `MaxStepsPerPump` | 5 | 单次 Pump 步数上界（帧预算/追帧上界） |
| `CatchUpPolicy` | `CatchUpDrop` | 超界时间的丢弃/降级策略 |
| `MaxAccumulatedSteps` | 4×上界 | Defer 策略下债务总量上限 |
| `ErrorPolicy` | `ErrorAbort` | 系统异常隔离策略 |
| `HotSwapRollback` | false | 热更新失败是否回退上一版本 |
| `OnEvent` | nil | 可观测事件回调（步提交/跳过/丢弃/过载/热更新/回退） |

## 可观测性

- `Result`：每次 Pump 的提交/跳过/丢弃步数、过载标志与错误，均可区分。
- `Stats()`：当前步号、暂停/缩放、累加器余量与欠债步数。
- `Event`：通过 `OnEvent` 回调上报步提交、步跳过、时间丢弃、过载、热更新与回退。

## 复现与验证

```sh
go test ./...        # 全部确定性/追帧/暂停缩放/异常隔离/热更新/快照/过载测试
go test -race ./...
```

测试全部使用 `ManualClock`，不依赖真实时钟与外部引擎。
注意：`Loop` 不是并发安全的，所有方法须由单一驱动 goroutine 调用。
